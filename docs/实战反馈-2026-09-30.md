# sageread-mcp 实战反馈 · 2026-09-30（第一次真实任务）

> 任务背景：AI Agent（Kimi Work，非 Claude/Cherry）在没有任何 MCP 客户端挂载的情况下，通过 stdio 直接驱动 sageread-mcp，对《墓碑》EPUB 做向量语义检索，核销一组历史数字口径。SageRead 发行版运行中（数据目录 `com.bettersageread.app`）。
> 结论：**核心链路一次打通，证据质量超出预期**。以下按「顺畅 / 摩擦 / 建议」记录。

## ✅ 顺畅的部分

1. `list_books`、`semantic_search` 端到端可用；`/embed` 本地通道（mcp-local.json 凭据）工作正常，密钥不出 app 的设计实际生效。
2. **出处信息是杀手级特性**：每个命中块带书名/章节/文件路径/块位置 + `get_chunk_context` 提示，Agent 能把证据精确指回原书（本次引用格式：`part003.md 块 99/193`）。
3. 只读打开 WAL 中的数据库、与运行中的 app 并发无冲突。
4. 检索质量高：查询「信阳地区总人口 饿死人数」直接命中含三套统计口径的段落（相似度仅 17% 但内容完全正确）——**相似度数值偏低不代表没命中，建议文档里提醒用户不要按阈值过滤**。

## ⚠️ 摩擦点（按严重程度排序）

### F1 · 数据目录解析漏了当前发行版 bundle id（功能性 bug）

- `resolveDbPath()` 的候选列表是 `["com.bettersageread", "com.xincmm.sageread"]`，但当前发行版实际写的是 **`com.bettersageread.app`**。
- 后果：不设环境变量时，MCP 会静默落到旧的 `com.xincmm.sageread` 目录——读错数据库，且那边没有 `mcp-local.json`，`semantic_search` 会报「SageRead 未运行」的误导性降级提示（其实 app 明明在跑）。
- 本次绕行：`SAGEREAD_DB_PATH=...\com.bettersageread.app\database\app.db`（由于 `APP_DIR` 从 db 路径反推，mcp-local.json 解析也随之修正）。
- 建议：候选列表加入 `com.bettersageread.app`（并置于首位）；或做成扫描 `%APPDATA%` 下所有 `com.bettersageread*` / `com.xincmm.sageread*` 目录、按 `mcp-local.json` 新鲜度 + db 修改时间自动选活动实例。

### F2 · 普通书籍（EPUB）没有正文阅读工具（功能缺口）

- 论文有 `read_paper` / `read_paper_section` / `get_paper_toc`，书籍（EPUB）只有向量检索 + `get_chunk_context`（radius 上限 3 块）。
- 实战后果：命中一个关键块后想通读「一、信阳事件」整章（193 块）做不到，只能 3 块 3 块地扩。
- 建议：加 `get_book_toc(book_id)`（列出 mdbook 文件清单/章节）和 `read_book(book_id, file_order, chunk_range)`；或把 `get_chunk_context` 的 radius 上限放宽并支持跨文件。

### F3 · `get_chunk_context` 参数名误导（易用性）

- 参数叫 `paper_id`，但书籍域传的是 book id（检索结果里的 `上下文提示` 也写成 `paper_id='210b...'`）。建议改名 `id` 或 `target_id`，或在描述里明确「书籍传 book id」。

### F4 · 环境兼容性备注（非 MCP 的锅，但值得文档化）

- 本次调用方是 Kimi Work 的 Git Bash/Python，其 `node` 是 shell/cmd shim，`CreateProcess` 直接执行会 `WinError 2`；调用方需经 `cmd /c` 包装。已在通用驱动 `F:\Tools\mcp_call.py` 内置处理。sageread-mcp 的 README「客户端配置」一节如能被更多 Agent 环境直接消费，可考虑附一句 stdio 驱动的注意事项。

## 🔧 本次搭建的调用链（沉淀）

```
F:\Tools\mcp_call.py  （通用 stdio MCP 调用器，含 initialize 握手 / Windows cmd 包装）
  → node F:\MyProjects\sageread-mcp\dist\index.js
  → env SAGEREAD_DB_PATH=%APPDATA%\com.bettersageread.app\database\app.db  （绕过 F1）
  → semantic_search {query, scope:"books", book_id:"<墓碑 id>"} 
  → app 内 /embed 本地通道向量化（app 须运行）
```

《墓碑》书 id：`210b093441669653de55a5109238fc67`（EPUB，第一章「信阳事件」= part003.md，共 193 块）。

调用示例：

```bash
python F:\Tools\mcp_call.py --server "node F:/MyProjects/sageread-mcp/dist/index.js" \
  --env "SAGEREAD_DB_PATH=%APPDATA%\\com.bettersageread.app\\database\\app.db" \
  --call semantic_search --args '{"query":"...","scope":"books","book_id":"210b...","top_k":5}'
```

### F5 · 外部来源 EPUB 质量差异导致「只能召回、不能直读」（2026-10-02 补）

- 案例：《圣殿》（自找 PDF 转 EPUB 入架）：结构塌为单一大章（正文挤在无小节号的超大章节），且源文件含模型幻觉式循环重复段。后果：向量召回可用，按章节直读不可用。
- 建议：① 转换器加「结构体检」报告（章数/平均章长/异常超长章预警）；② 书架支持「坏结构」标记，提示该本仅适合语义检索；③ 可选：重复段检测——连续 N-gram 循环是扫描版/幻觉源的典型指纹，导入时提示。
